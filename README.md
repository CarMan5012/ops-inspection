# 运维巡检平台

本系统是一个轻量级的 **Web 运维巡检配置后台**。它支持对 Grafana、Kibana/Elastic 及任意普通网页进行自动化截图，按日期计划定时运行，自动生成 `.docx` 格式的 Word 巡检报告，并可发送钉钉通知。

---

## 1. 核心业务流程与架构

系统主要包含 **任务调度、自动化登录与截图、图像后处理、报告生成、钉钉通知** 五个核心模块。以下是系统在触发一次巡检任务时的底层逻辑流程图：

```mermaid
graph TD
    A([定时任务 / 手动触发]) --> B[初始化浏览器环境]
    B --> C{是否关联登录认证?}
    C -- 是 --> D{是否存在 Session 缓存?}
    D -- 否 --> E[Playwright 模拟打开登录页面]
    E --> F[自动填充账号密码并点击登录]
    F --> G[加密保存 Session 状态至本地]
    G --> H[载入目标巡检网页]
    D -- 是 --> I[解密并载入已有 Session 状态]
    I --> H
    C -- 否 --> H
    H --> J[检查访问并等待页面渲染]
    H -. 登录态失效重定向 .-> F
    J --> K{是否开启真实浏览器窗口截图?}
    K -- 是 --> L[通过 Xvfb 虚拟显示 + mss 物理截图]
    K -- 否 --> M[Playwright 网页级截图 (视口/整页)]
    L --> V{图片有效?}
    M --> V
    V -- 否 --> H
    V -- 是 --> N[Pillow 拼装任务栏底栏 & 绘制真实时钟]
    V -- 是 --> O[Pillow 图像后处理: 添加斜体平铺水印]
    N --> P[生成并排版 .docx Word 报告]
    O --> P
    P --> Q{是否开启钉钉通知?}
    Q -- 是 --> R[发送钉钉通知]
    Q -- 否 --> S([巡检任务结束])
    R --> S
```

## 2. 技术栈

* **Web 后端**：基于 **FastAPI** + **Uvicorn**，提供高性能的异步接口和静态资源托管。
* **定时调度**：基于 **APScheduler `DateTrigger`**。系统计算下一次具体执行时间，到点后再安排下一次；不用 Cron 表达式或 `CronTrigger`。
* **安全数据库**：基于 **SQLite**，通过 **SQLCipher** 拓展进行物理加密，确保即使数据库文件被拷走，敏感配置数据也无法被读取。
* **网页自动化**：基于 **Playwright (Chromium)**，通过有头或无头模式加载目标系统，支持全自动化登录表单填充与状态缓存。
* **物理窗口截图**：在容器内启动 **Xvfb** (虚拟帧缓冲) 构建图形环境，并利用 Python 的 **mss** 库截取真实的 Chromium 物理桌面窗口，还原浏览器地址栏和标签。
* **图像后处理**：基于 **Pillow (PIL)**，进行平铺防伪水印叠加，并模拟 Windows 任务栏时钟，按照截图时间动态渲染右下角时间。
* **报告排版**：基于 **python-docx**，未选模板时自动排版；也可在 Web 页面上传 `.docx` 模板并为各巡检任务选择，自动插入截图生成报告。
* **前端展示**：使用 Vue 3、TypeScript 和 Vite 构建管理界面；图标来自腾讯开源的 TDesign Icons（MIT）。前端构建产物由 FastAPI 提供，容器构建时自动编译。

## 3. 本地开发调试

前端代码在 `frontend/`。修改页面后，可在该目录执行 `npm ci` 和 `npm run build`；构建文件写入 `app/static/vue/`。`npm run typecheck` 可单独检查 Vue 与 TypeScript。管理界面使用 Vue 前端，旧的 `/legacy` 地址会跳转到当前界面。

### 3.1 环境依赖
您需要安装 Python 3.11+ 并在本地安装 Chromium 浏览器依赖。

### 3.2 运行步骤（以 Windows PowerShell 为例）
```powershell
# 1. 创建并激活虚拟环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. 安装依赖包
pip install -r requirements.txt

# 3. 安装 Playwright 底层 Chromium 浏览器
playwright install chromium

# 4. 运行后台服务 (本地调试默认会在数据目录自动创建 app-secret.key)
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
首次访问系统：`http://localhost:8000/`；初始化后使用页面中设置的访问路径前缀。

## 4. 容器化部署

### 本地重复测试（Docker Compose）

`compose.local.yml` 只启动应用容器，无需 `.env`。在项目目录运行：

```powershell
docker compose -f compose.local.yml up -d --build
docker logs inspection-local 2>&1 | Select-String '^SETUP_CODE='
```

访问 `http://127.0.0.1:8800/`。后续更新重复执行第一条命令；Compose 管理的数据卷会保留初始化设置和测试数据。若 8800 端口被占用，可修改 `compose.local.yml` 中的主机端口。`docker compose -f compose.local.yml down` 只停止并删除本地容器；仅在确定要清空测试数据时使用 `down -v`。

### 单容器部署（无 `.env`）
只部署巡检系统。Grafana、Kibana 是外部网站，在登录后通过“网站连接”配置，无需随本系统启动。

```bash
docker build -t ops-inspection:latest .
docker volume create inspection-data
docker run -d --name inspection-report --restart unless-stopped \
  -p 8800:8000 -v inspection-data:/app/data ops-inspection:latest
docker logs inspection-report 2>&1 | grep '^SETUP_CODE='
```
首次访问 `http://localhost:8800/`，页面会进入分步初始化。输入上述命令获取的一次性码，设置管理员账号、系统名称和访问路径前缀。前缀留空时继续使用根路径；填入 `/ops` 时，完成后跳转到 `/ops/login`。根路径始终可以进入系统。初始化前重启会再次打印同一个码；初始化后该码失效。命名卷包含加密数据库、截图、报告和自动生成的主密钥，必须持久化并备份。端口映射中的 `8800` 可按部署环境调整。

生产镜像不读取 `.env`；应用配置在页面完成。首次初始化只支持全新数据目录。检测到没有安装记录的旧数据库时，应用会拒绝启动，不会开放初始化入口。
管理员用户名和密码、系统名称、访问路径前缀、节假日接口地址可在“系统设置”修改；钉钉机器人、网站连接、截图尺寸及任务计划也在页面配置。应用时区固定为北京时间（`Asia/Shanghai`）。容器端口和数据卷属于 Docker 启动参数；加密主密钥由程序在数据卷中自动生成。

## 5. 安全与密钥设计

登录接口按 ASGI 服务提供的客户端 IP 限制尝试次数：5 分钟内最多 8 次，超出后暂停 5 分钟；成功登录会清除计数。反向代理部署时，若未配置可信代理转发，限速按代理的连接地址计算。

新部署在首次访问时设置管理员密码，只保存 scrypt 哈希。此后可在“设置 → 安全设置”中修改密码；修改后原登录会话失效。应用敏感字段使用 `cryptography` 的 Fernet 加密。

为了保障生产环境下各项凭证（目标系统密码、钉钉密钥）的安全，系统设计了双重密钥体系：

1. **数据库物理加密**：默认使用自动生成的应用主密钥作为 SQLCipher 数据库密钥。
2. **应用敏感字段加密**：
   * 系统的主密钥，用于通过 Fernet/AES 算法在应用层对敏感输入（如登录凭证、钉钉 Token）进行二次加密。
   * 系统在持久化数据目录下自动生成 `app-secret.key` 文件。只要该目录不丢失，密钥即保持一致。

## 6. 特色功能详解

* 截图按截图项配置的“等待元素”和“手动等待”执行；Grafana 截图会尝试暂停自动刷新，并等待可见面板出现图表或正文。Kibana 截图会等待可见面板完成加载，遇到查询错误或等待超时会记录具体面板并按配置次数重试。面板显示“无数据”时仍保存截图，并在结果中标明。
* “单次页面截图超时”从登录完成后开始计算，限制一次页面访问、等待、截图和图片处理；“单项最长耗时”从该截图项开始计算，包含登录和所有重试，默认 240 秒。达到总时限后停止重试，不保存未完成的图片。

### Grafana 数据监测

* Grafana 看板截图成功后，系统复用浏览器登录状态，读取看板关联的 Prometheus 数据源，再通过 Grafana 数据源代理读取当前告警和已加载的告警规则；无需另填 Prometheus 地址或凭据。
* 监测结果分别显示为“发现告警”“暂无告警”“未配置规则”“无法判断”。“暂无告警”只表示相关数据源中已加载的规则当前没有活跃告警，不代表截图画面里的每个指标都正常。
* 这些是数据源范围内的当前告警，可能包含看板未展示的指标。Grafana API 权限不足、数据源代理不可用或规则读取失败时，记录具体原因并显示“无法判断”。
* Word 报告记录截图与失败原因；启用钉钉通知时会发送巡检结果摘要。

### 6.1 真实浏览器窗口截图 (Xvfb + mss)
* **原理**：系统在 Xvfb 虚拟桌面中启动 Openbox 和有界面的 Chrome，按前台 Chrome 的完整窗口外框截屏，保留标签、地址栏和右上角的窗口按钮。该模式使用 SwiftShader 软件渲染，以支持 Kibana 地图等 WebGL 图表。
* **配置方式**：在新建截图项时勾选 `real_browser_capture`（真实浏览器窗口截图）选项。
* **限制**：该模式下浏览器渲染仅支持 **视口截图 (viewport)**。如果需要截取整页长图，请取消勾选此项以回退至标准 Playwright 无头页面截图模式。
* **窗口定位**：截图时读取目标 Chromium 窗口的实际位置和尺寸；窗口超出虚拟屏幕或尺寸不符时明确报错，不截取显示器的固定区域。
* **显示缩放**：浏览器按配置倍数显示，窗口的逻辑尺寸同步换算；例如最终图片为 3840×2160、1.5 倍缩放且启用任务栏时，浏览器窗口为 3840×2088 物理像素，任务栏占底部 72 像素。
* **窗口独占**：同一服务进程中的真实窗口巡检依次执行，避免两个浏览器窗口同时争用虚拟桌面。
* **故障恢复**：页面失败时使用新的页面环境重试；浏览器失联或关键操作卡住时关闭并重启浏览器，再执行剩余重试。

### 6.2 自动登录与 Session 自愈
* **表单模拟**：配置认证方案后，系统会在第一次加载页面前，自动前往 `Login URL`，定位用户名和密码输入框，填充凭证并提交。
* **状态持久化**：登录成功后，系统会将其 Session (Cookies、LocalStorage 等) 经主密钥加密后序列化到磁盘（`browser-state/`）。后续截图任务会直接载入缓存，省去频繁登录操作，提高运行速度。
* **Session 自愈**：若截图加载中发现被重定向回了登录页，系统会清除失效缓存与 Cookies，并在当前浏览器窗口重新登录。
* **多账号隔离**：同一巡检任务可为每个页面选择不同的网站连接。登录状态按认证配置 ID 单独保存，同一 Grafana 使用多个账号时不会共用缓存。
* **添加页面**：新增 Grafana 或 Kibana 截图项时，可先选择网站连接，再搜索并点选仪表盘，系统自动带入地址；Kibana 和普通网页也可手动填写地址。任务详情也支持多选 Grafana 看板或一次粘贴多个 URL。只有网址唯一对应一套连接时才自动匹配账号；批量保存前逐项检查页面和登录。

### 6.3 图像后处理 (任务栏 & 水印)
* **动态任务栏**：真实窗口截图会在配置的最终尺寸内为任务栏预留空间。例如配置 3840×2160 时，浏览器窗口和底部 Windows 风格任务栏合成后仍为 3840×2160，并按截图时间绘制时钟。
* **斜体水印**：支持自定义文字（包含截图时间、巡检人员姓名等占位符），在整张截图上平铺旋转水印，兼顾安全合规性与防伪需求。

## 7. 持久化数据目录结构

应用数据均保存在容器的 `/app/data` 下。本地 Compose 使用 `inspection-data` 命名卷；生产 `docker run` 可将宿主机目录挂载到 `/app/data`。目录结构如下：

```text
data/
  ├── app.db               # 加密过的 SQLite 数据库文件
  ├── app-secret.key       # 自动生成的解密主密钥文件
  ├── reports/             # 所有生成的报告、截图与周期归档
  │   └── YYYY/
  │       └── MM/
  │           ├── DD/     # 当天截图与最终日报
  │           │   ├── HH-MM-SS_截图项.png
  │           │   └── 报告标题-YYYY-MM-DD.docx
  │           ├── 周报_起始日期_至_结束日期.zip
  │           └── 月报_YYYY-MM.zip
  ├── templates/           # 用户上传的 Word 模板
  ├── taskbar-templates/   # 用户上传的截图底栏图片
  ├── logs/                # 存放巡检执行的系统运行日志
  └── browser-state/       # 存放加密后的浏览器 Session 缓存 JSON 文件
```

## Word 报告模板

在“模板管理 → 报告模板”上传 `.docx` 文件，再到“巡检任务 → 编辑 → 报告与通知”选择模板。未选模板的任务自动排版。模板上传后保持原文件不变；使用中的模板需先从任务上取消选择，才能删除。

模板正文需有 `yyyy年mm月dd日` 或 `yyyy-mm-dd` 日期占位符，并包含“巡检时间：上午”和“巡检时间：下午”两个段落。两个时段下分别添加相同的数字开头章节，例如 `1. 服务器资源`。截图项的报告章节要与模板章节一致。当前生成器会清理章节标题和下一标题之间的占位文字，并在该位置写入截图及失败说明。

## 截图底栏

“模板管理 → 底栏模板”由后端返回 4 张预置底栏和用户上传的底栏，可上传 PNG、JPEG 或 WebP 宽幅横条图。在截图项编辑页开启任务栏后，默认选择“自动轮换”：同一次巡检的所有自动模式截图项共用一张预置底栏，不同巡检可能切换。手动指定的截图项固定使用所选图片。使用中的上传底栏需先从截图项取消选择，才能删除。

## 定时巡检与节假日

新建巡检任务可选择每天、周一至周五、指定星期、每月多个日期、工作日或非工作日，并设置多个执行时间。每月所选日期在当月不存在时自动跳过。工作日按国内节假日与调休补班数据判断；周一至周五只按星期判断。系统启动时检查节假日主接口，失败时切换备用接口，此后每天重新检查一次。两个接口都不可用时，页面自动隐藏工作日和非工作日选项；已有任务只在本地缓存能够确认当天类型时执行。旧简单计划会在启动时转换，并在 `data/schedule-migration-backup.json` 留存原规则；无法安全转换的旧规则暂停自动执行，等待在页面重新设置。

默认主接口为 `timor.tech`，备用接口为 `publicapi.xiaoai.me`。Vue 图标和页面资源随应用构建打包，访问页面无需连接外部静态资源服务。
